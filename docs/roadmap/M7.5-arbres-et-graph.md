# M7.5 — Arbres et Graph

**Objectif** : les relations du monde racontent la même histoire partout. Une relation tracée dans un arbre apparaît dans le Graph et dans « Cité dans » de la carte. Un nouvel arbre peut partir de ce que le monde sait déjà : les cartes reliées et leurs relations, placées par génération. Et le Graph dit à quoi il sert et pourquoi deux cartes sont liées.

**Origine** : décisions de Clément du 03/10 après la recette M7 (« les relations des arbres doivent apparaître dans le Graph » ; « une autodétection des cartes déjà présentes des personnages… dans l'arbre qu'on crée, il y a déjà les personnages avec les relations » ; « je n'ai pas très bien compris l'utilisation du Graph »). Questions ouvertes de M6 tranchées au passage : relations des arbres dans le Graph (oui) et « Cité dans » depuis les arbres (oui).

**Specs** : `docs/features/04-graph.md`, `docs/features/05-relation-tree.md`, `docs/features/01-cartes-et-types.md` (propriétés). **Décision** : ADR 0007.

**Choix de conception** (ADR 0007) :
- **Une relation d'arbre est un lien du monde.** Le Graph compte les relations tracées entre deux cartes dans les arbres (toutes les variantes, sans doublon), à côté des citations et des propriétés. Un enfant rattaché au lien d'un couple (jonction) est relié à chacun des deux.
- **Un arbre cite les cartes qu'il montre**, comme une map cite ses pins : « Cité dans » de la carte liste l'arbre (nouveau type de lien `tree`).
- **Une propriété de lien peut porter une relation** (« Parents » = *parent de*, « Conjoint » = *conjoint de*…) : ses valeurs deviennent des relations connues, utilisables par les arbres.
- **Pas de personnage deviné par le nom de son type** (les types sont libres) : les cartes reprises dans un nouvel arbre sont celles que relient des relations connues (autres arbres, propriétés-relations).
- **Un arbre reste un document à part** : le reprendre copie les relations connues au moment où on le demande ; ensuite, l'arbre et les fiches vivent chacun leur vie (pas de synchronisation à double sens).

**Ordre d'exécution** : 7.5.1 → 7.5.2 → 7.5.3 → 7.5.4 → 7.5.5, et la recette 7.5.6 en dernier.

## 7.5.1 — Les relations des arbres dans le Graph (#302)
**Branche** : `feat/graph-tree-relations` · **Dépend de** : —

- [ ] Le Rust ajoute au Graph les relations tracées entre deux cartes dans les arbres vivants (toutes variantes, une fois par paire et par type ; une jonction relie l'enfant aux deux bouts du lien)
- [ ] Chaque lien du Graph dit d'où il vient : citations, propriétés (leur nom), relations (leur nom, l'arbre)

**Critères d'acceptation** : un lien parent tracé entre deux cartes dans un arbre relie ces cartes dans le Graph ; il disparaît quand l'arbre va à la corbeille.

## 7.5.2 — « Cité dans » depuis les arbres (#303)
**Branche** : `feat/tree-backlinks` · **Dépend de** : —

- [ ] Migration : un type de lien `tree` (l'arbre → chaque carte qu'il montre), tenu à jour à chaque enregistrement de l'arbre, retiré avec lui
- [ ] « Cité dans » d'une carte liste les arbres où elle figure ; un clic ouvre l'arbre

**Critères d'acceptation** : une carte posée dans un arbre a cet arbre dans « Cité dans » ; retirée de l'arbre, elle ne l'a plus.

## 7.5.3 — Propriétés-relations (#304)
**Branche** : `feat/relation-properties` · **Dépend de** : —

- [ ] Migration : une propriété de lien (carte ou cartes) peut porter un type de relation du monde
- [ ] Dans la définition de la propriété : « C'est une relation : aucune / Parent de / Enfant de / Conjoint… » ; dans le Graph, ses liens portent le nom de la relation

**Critères d'acceptation** : une propriété « Parents » réglée sur *parent de* fait de ses valeurs des relations connues.

## 7.5.4 — Un nouvel arbre qui part des relations connues (#305)
**Branche** : `feat/tree-from-known` · **Dépend de** : 7.5.3

- [ ] Commande `known_relations` : les cartes reliées et leurs relations, venues des arbres et des propriétés-relations (sans doublon, sens normalisé)
- [ ] Un arbre vide propose « Reprendre les relations connues (N cartes, M relations) » ou de commencer vide ; aussi dans le menu de l'arbre, pour ajouter ce qui manque
- [ ] Placement par générations : parents au-dessus, enfants dessous, couples côte à côte, l'enfant d'un couple rattaché au lien du couple ; annulable d'un `Ctrl+Z`

**Critères d'acceptation** : dans un monde où Aragorn a pour parents Arathorn et Gilraen (propriété ou autre arbre), un nouvel arbre reprend les trois, le couple et l'enfant rattaché.

## 7.5.5 — Comprendre le Graph (#306)
**Branche** : `feat/graph-explained` · **Dépend de** : 7.5.1

- [ ] « À quoi sert le Graph ? » : une courte explication dans la page (chaque carte est un point, chaque trait dit que deux cartes sont liées, son épaisseur combien de fois ; à quoi ça sert : voir les groupes, les cartes isolées, naviguer)
- [ ] Une carte sélectionnée liste ses liens et leur origine (« Gandalf — cité 2 fois, parent de (arbre Maison d'Elendil) »), chaque ligne ouvre la carte

**Critères d'acceptation** : sans rien connaître du Graph, on comprend en le lisant pourquoi deux cartes sont reliées.
